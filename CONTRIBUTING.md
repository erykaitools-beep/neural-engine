# Contributing

The most useful first contribution is a result another researcher can check, including a failed replication. Start with [the reproduction guide](docs/reproduction.md). Use GitHub issues or a pull request; a new training run is not required to report a scoring or documentation problem.

For a reproduction, include the Git commit, manifest status, Python and NumPy versions, OS/architecture, command, study, seed, checkpoints compared, and the first mismatch if any. Distinguish re-scoring archived trials, replay on the same inputs, and replication on independent data. Do not upload account names, machine paths, service logs, secrets, or other people's data.

For an experiment, state the hypothesis, comparison group, independent unit, input split, resource budget, tie handling and predeclared criterion **before** looking at the outcome. Keep old evidence immutable: add a new named study rather than editing stored responses or tolerances. Do not call code review or reanalysis a new cohort.

Disclose material AI assistance and the origin and licensing of submitted code or data. Only contribute material you have the right to share. Pending approval of the code/data licenses, do not assume this review candidate grants redistribution rights.
